# On-device (offline) rice-leaf diagnosis

The **Submit Field Report** screen runs the rice-leaf classifier fully offline with
[`react-native-fast-tflite`](https://github.com/mrousavy/react-native-fast-tflite),
so a farmer with no signal still gets an instant estimate. The Django backend always
re-runs the diagnosis on upload and **that result stays authoritative** - the
on-device output is advisory and is never sent to the server as a result.

## Pieces

| File | Role |
|---|---|
| `assets/model/rice_leaf.tflite` | The model. Generated by `manage.py export_tflite` in the backend (copied here automatically). |
| `assets/model/rice_leaf_labels.json` | Class index -> label (`{"0":"BLB","1":"HEALTHY","2":"BLAST"}`). |
| `src/ml/leafModel.ts` | Loads the model, decodes+resizes the JPEG, runs inference, returns `{disease, confidence, probabilities}`. Degrades gracefully when the native module is absent (Expo Go). |
| `src/screens/kagawad/SubmitReportScreen.tsx` | "On-device diagnosis" toggle + result card. Runs automatically when a photo is picked. |
| `metro.config.js` | Adds `tflite` to `assetExts` so the model bundles. |
| `app.json` `plugins` | `expo-dev-client` + `react-native-fast-tflite` config plugins. |
| `eas.json` | `development` / `preview` / `production` build profiles. |

The `.tflite` graph rescales `[0,255]` input and applies softmax internally, so the
app feeds a `Float32Array` of raw RGB pixels shaped `[1,224,224,3]` and reads back 3
probabilities in label order.

## Why this needs a native build

`react-native-fast-tflite` is a native module. **It does not run in Expo Go.** In
Expo Go the screen still works - the toggle is disabled and shows why, and upload
(online diagnosis) is unaffected.

## Build & run

From `oryzawatch_mobile/`:

```powershell
# 1. install deps at Expo-correct versions
npx expo install expo-dev-client
npm install react-native-fast-tflite jpeg-js base64-arraybuffer
npx expo install --check          # reconcile any version drift

# 2. regenerate the model whenever the backend model changes
#    (run in ../oryzawatch_backend)   ..\.venv\Scripts\python.exe manage.py export_tflite

# 3a. local native build (needs Android Studio / Xcode)
npx expo run:android              # or: npx expo run:ios
#     -> installs a dev build; `npx expo start --dev-client` to attach Metro

# 3b. or cloud build with EAS (no local SDK needed)
npm install -g eas-cli
eas login
eas build --profile development --platform android   # dev client, .apk
#   install the .apk, then: npx expo start --dev-client
```

For a shareable offline demo build use `--profile preview` (release `.apk`, no Metro
needed).

## Updating the model

1. Retrain in the backend (`train_leaf_model`, then `export_tflite`).
2. `export_tflite` overwrites `assets/model/rice_leaf.tflite` here.
3. Rebuild the dev/preview client (the `.tflite` is bundled at build time). A JS-only
   reload is **not** enough - the asset is native.

## Notes

- Preprocessing is a nearest-neighbour resize in JS (`src/ml/leafModel.ts`). It
  matches the backend closely enough for an estimate; the two models are trained
  separately (PyTorch on the server, Keras->TFLite here) so a few percent of
  disagreement on BLB vs BLAST is expected.
- `warmUpLeafModel()` is called on screen mount so the first scan isn't slow.
- To shrink the app, run `export_tflite --quantize` (~2 MB vs ~8 MB, minor accuracy cost).
